**★ RECORD GRAMMAR FIX (2026-07-05, important):** conditioned tadj records use a **13-byte middle**, not 14. The byte after tag\0 is a "condition flag": if 0 → no condition (that byte is consumed as part of the standard 14-byte middle = flag_u8 + u32(0) + f32 + f32 + u8); if nonzero → it's the start of the condition z-string (e.g. TARGET_SIZE>=2, ENHANCED==1), read it, THEN only 13 bytes follow (u32(0) + f32 + f32 + u8) before u32 param_count. Parser rule: `has_cond = b[after_tag]!=0; if has_cond: read cond; middle = 13 if has_cond else 14`. This is why sp_step_atk00's Warp (and any conditioned record) misparsed with the old 14-assumption. Supersedes the ambiguous note in [[bros-file-formats]].
