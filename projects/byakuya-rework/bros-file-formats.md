**pl022.tadjpkg** (binary, 887KB): magic "actadj_pkg", u32@0x1c unknown (not validated; toolkit ignores it), u32@0x20 entry count (168), then 72-byte entries at 0x24: 64-byte name + u32 offset + u32 size. Entries named `1_normal_*` (form 1) / `2_evo_*` (form 2). Base has atk_lo01-06 (lo1-3 sword, lo4-6 petal); evo only lo01-03. Blobs: "adjb" + path (e.g. `1_normal\attack`) + action name, then tagged records: `[u32 uid] Tag\0 [pad/floats: ~f32 zero, f32 start-frame, f32 end-frame] \0 u32 param_count, key\0value\0 pairs`. Record types: Attack_Melee, ComboStart, CancelTiming, Enhance, SE_OneShot, Effect_*, Warp, SuperArmor, etc.

**Stance mechanism**: `Enhance` record toggles the "固有強化" state. Params: enhance_start (1=petals on, 0=off), enhance_mode=1, max_val=-1.0, init_val=auto, enhance_active=0. Found in: atk_ex01 (start=1), atk_ex05/ex06 (start=0), sp_atk01 (start=1, frame 57), sp_atk01_1 (start=0).

**Record grammar addendum (2026-07-04, SOLVED the "variant" mystery; REFINED 2026-07-05):** the byte after tag\0 is a "condition flag." If 0 → NO condition, and that byte is the first of the standard **14-byte middle** (flag_u8 + u32(0) + f32 + f32 + u8). If nonzero → it's the start of an OPTIONAL condition z-string (read it), and then only a **13-byte middle** follows (u32(0) + f32 + f32 + u8) before u32 param_count. I.e. conditioned records are 13, unconditioned 14 — the condition replaces the flag byte. (Old "14-byte middle for all" note was wrong for conditioned records; caused Warp/ENHANCED-record misparse. Verbatim transplant of a conditioned record is always safe regardless.) Known condition: `ENHANCED==0`/`ENHANCED==1` (vanilla uses on atk_gr02/03, syunpo_out_just to swap sword/petal fx per stance) — this gates individual records on the 固有強化 flag. Effect_Loop/Effect_OneShot = standard grammar + optional condition + exactly 32 kv pairs: eff_name, start_trigger (EMPTY = fire at middle f32#1 frame, no anim event needed — charge_eff precedent), end_trigger (T32_Kill&Fade etc.), sub_trigger1-8 + _wait×8, pos/rot/scl ("0.000000,..." SJIS), bind_comp=body, bind_joint=ido, bind_not_rot, bind_follow_pos/rot/scl, delete_method=追従しながら消える, rend_timing=前半描画, rend_priority, z_sort_off. 22 of 174 entries still fail strict parse (other variants: bone-bound Syunpo oneshots etc.) — insert-at-front avoids parsing them.

**Exact record grammar** (confirmed on all Enhance/SE/Voice/ComboStart records): `u32 uid | tag z-str | u32(0) | u8(0) | f32 start-frame | f32 end/param | u8(0) | u32 param_count | param_count × (key z-str + value z-str)`. The 14 bytes between tag and param_count are MANDATORY — a 13-byte version (missing the first u8) desyncs the engine's record stream and crashes the game at character load (caused Berg's first crash, 2026-07-02). Entry blob = "adjb" + 3 z-strings (path, entry name, action name — 3rd can differ from 2nd) + 17 fixed bytes (f32 -1.0, i32 -1, u32 0, f32 1.0, u8 0) + u32 record_count + records + small footer (4-19 trailing bytes, keep verbatim). Some record types (certain Effect_OneShot etc.) have variants beyond this grammar — insert-at-front + count bump avoids needing to parse them. Record order in stream is not frame-sorted (order-insensitive). tcmbpkg node _uniqueID namespace is per-table (base max 123, evo max 163 in vanilla).

**pl022.tcmbpkg** (Shift-JIS JSON-ish text, trailing commas): header, 23 `variable` defs, then tables `combo` (base) + `evo_combo` (evo). Nodes: _uniqueID, input_text (Pad_R_Left=lo, Pad_R_Up=hi, Pad_R_Right=ex, Pad_R_Down=step-atk, Pad_R1=grab/clash, Pad_R2=overatk/spbreak, AutoCombo, RecvEvent+input_event), push, access_text (entry point, e.g. start_lo), jump_tip/jump_table_name/jump_access_text (cross-table jump), nexts (uid list), variables[23]. Var[1] in_powerup (1=only while SP trigger held), var[6] enhance (-1 only-when-off / 1 only-when-on / 0 ignore), var[7] reiryoku_cost. Base start_lo→[atk_lo01(enh-1), atk_lo04(enh1)]. Evo table already uses enhance=-1 gates (sp_overatk01) → state machinery live in evo. Awakening action = 1_normal_ct_ct_evolve.

Decoded copy of tcmbpkg: outputs/pl022_tcmb.txt (UTF-8). Toolkit exe = PyInstaller Python 3.13, source extractable (pyinstxtractor-ng); it only does same-length in-place edits — size-changing edits require rebuilding the offset table ourselves.

**pl022.tactpkg** (the real path to sword-in-evo): outer `PZZEtact` header = magic(8) + u32 decompressed size + u32 0 + u32 0x18 + u32 0, zlib stream at 0x18. Decompresses to `actmng_pkg` (~70MB), same 0x24/72-byte table, 210 entries. Action entries = JSON-ish `act_data`: path key "1_normal\attack\atk_lo01", per-target sections (body.tmo_name="pl022_atk_lo01" = motion ref, weapon0_0, head, hair...), start/end/play/fusion frame, next_flow/next_name (["1","0","0"]/["ntrl_in"]). Four entries named "pl022" are nested sub-packages: acttmo_pkg (68.5MB — ALL motions both forms, ONE shared pool), acttmv_pkg (weapon motions), actmtl_pkg, motblend_file. **Sword-port recipe**: clone act_data entry → "2_evo\attack\evo_atk_loXX" keeping tmo_name at base motion; clone tadjpkg blob (fix its 3 header strings); route in tcmb evo table (node name without "evo_" prefix, e.g. node atk_lo04 → action evo_atk_lo04). Other pl022 rar files: .tmd2/.lds/.cphy=models, .cat, .bnk+pl022.txt=Wwise audio (txt=event name dictionary), tdemopkg=cinematics, AiActList/fsv=obfuscated _cso_, Adv_Pl022_Senkei00.vfxb = story-mode Senkei VFX (flavor for later!).

**.fsv/.cat `_cso_` cipher CRACKED**: format = `_cso_1_<seed>\n` header + ciphertext. Cipher = repeating 8-byte key, plaintext = (cipher_byte - key_byte) & 0xFF per position (key repeats every 8). Recover key per-column by maximizing printable/CSV chars. Decodes to `_csv0,<cols>\n<rows>`. cos_pl022.fsv=costume table (body/hair/face/weapon slots — Byakuya's weapon cols BLANK, weapon comes from default rig not costume); AiActList=AI combo CSV (has enhance col); AiAff=AI counter table. Keys differ per file (derived from seed). .lds/tactpkg/tadjdbpkg use zlib at 0x18 instead. Official fsv codec = game's `Script/fsv2csv.py`.
